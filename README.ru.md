# RSS Reader

[English](README.md) | Русский

Самостоятельный RSS/Atom-агрегатор новостей с бэкендом на FastAPI, базой данных SQLite и интерфейсом на Jinja2. Пользователь может добавлять собственные RSS/Atom-источники, читать статьи из разных источников в одной ленте, помечать материалы как прочитанные или избранные и искать по публикациям — без отдельного шага сборки фронтенда.

## Предварительный просмотр

Приложение представляет собой одностраничный интерфейс: боковая панель со списком источников и статистикой, центральная область с карточками публикаций и верхняя панель с поиском и кнопкой обновления. Темная и светлая темы подстраиваются под системные настройки. Макет адаптирован для десктопов и мобильных устройств.

## Возможности

- Добавление RSS/Atom-источников по URL с автоматической проверкой формата ленты
- Единая лента публикаций из всех добавленных источников
- Фильтрация по источнику, только непрочитанные или только избранное
- Поиск по названию публикации, описанию и названию источника
- Пометка публикаций прочитанными / непрочитанными и добавление в избранное / удаление из избранного
- Открытие оригинальной статьи в новой вкладке браузера
- Пагинация списка публикаций, чтобы большие ленты не загружали все записи сразу
- Обновление отдельного источника или всех источников одной кнопкой
- Панель статистики: количество источников, публикаций, непрочитанных, избранных, время последней выборки
- Темная и светлая темы, адаптирующиеся к системным настройкам
- Адаптивная верстка для десктопа и мобильных устройств
- REST API с интерактивной документацией Swagger по адресу `/docs`
- Защита от SSRF при загрузке пользовательских ссылок на источники (только HTTP/HTTPS, блокировка приватных/loopback/зарезервированных адресов, ограничение перенаправлений, размера скачиваемого содержимого и таймаута запроса)

### Компоненты

- **`app/main.py`** — Создаёт приложение FastAPI, регистрирует роутеры, монтирует статические файлы, инициализирует базу данных.
- **`app/models/`** — ORM-модели SQLAlchemy 2.x. `Feed` (источники) и `Article` (публикации) со связью «один ко многим» и уникальным ограничением `feed_id + guid`, которое предотвращает дублирование записей при обновлении.
- **`app/schemas/`** — Схемы Pydantic v2 для валидации запросов и сериализации ответов.
- **`app/api/`** — Обработчики REST-маршрутов с корректными HTTP-статусами и сообщениями об ошибках.
- **`app/services/rss_parser.py`** — Валидация URL (только HTTP/HTTPS), разрешение DNS и блокировка loopback/приватных/зарезервированных/многоадресных адресов, перенаправления (макс. 5), лимит размера скачивания 2 МБ, таймаут 15 секунд, парсинг RSS 2.0 / RSS 1.0 / Atom, нормализация дат публикации в UTC.
- **`app/services/feed_service.py`** — Бизнес-логика: создание/обновление/удаление источников, постраничный список публикаций с фильтрами и поиском, переключение прочитанного/избранного, агрегация статистики.
- **`app/templates/index.html`** — Один HTML-файл с боковым меню источников, центральной сеткой карточек статей, верхней панелью поиска и обновления, панелью статистики и диалогом добавления источника.
- **`app/static/js/app.js`** — Интерфейс на чистом JavaScript, который потребляет REST API; шаг сборки не требуется.
- **`tests/test_rss_reader.py`** — Набор тестов pytest, охватывающий валидацию URL, парсинг RSS/Atom, некорректный XML, предотвращение дублей, сохранение статуса прочтения, фильтры и поиск, эндпоинты API. Сетевые вызовы эмулируются с помощью локальных фикстур; реальные RSS-сайты не требуются.

## Установка

### Требования

- Python 3.11 или новее
- `pip` (входит в состав Python)

Docker, Node.js и внешние облачные сервисы не требуются.

### Windows (PowerShell)

```powershell
# Клонировать репозиторий
git clone <url-репозитория>
cd "RSS Reader"

# Создать и активировать виртуальное окружение
python -m venv .venv
.venv\Scripts\Activate.ps1

# Установить зависимости (включая dev-зависимости для тестов)
pip install -e ".[dev]"
```

### Linux / macOS


## Использование

### Запуск сервера

```bash
uvicorn app.main:app --reload
```

Приложение будет доступно по адресу http://127.0.0.1:8000.

Интерактивная документация API (Swagger/OpenAPI): http://127.0.0.1:8000/docs

### Основные сценарии пользователя

1. Откройте приложение в браузере.
2. Нажмите **Добавить** в боковой панели и введите URL RSS/Atom-ленты. Лента проверяется перед сохранением.
3. Просматривайте общую ленту публикаций в центральной области.
4. Используйте фильтры, чтобы показать только непрочитанные или избранные публикации, или отфильтровать по источнику.
5. Используйте поиск по названиям, описаниям и названиям источников.
6. Помечайте публикации прочитанными / непрочитанными и добавляйте в избранное с помощью кнопок на каждой карточке.
7. Нажмите **Открыть оригинал**, чтобы открыть исходную статью в новой вкладке.
8. Нажмите **Обновить всё**, чтобы получить новые статьи из всех источников.
9. Просматривайте статистику в боковой панели.

## Тестирование

В проекте 17 автоматизированных тестов. Запуск:

```bash
pytest
```

Тесты покрывают:
- Валидацию URL (только HTTP/HTTPS, блокировка неподдерживаемых схем)
- Блокировку хостов SSRF (localhost, loopback, приватные адреса)
- Парсинг RSS 2.0 и Atom
- Обработку некорректного XML
- Создание и сохранение источника
- Отклонение дубликата URL
- Предотвращение дублей при обновлении
- Сохранение статуса прочтения
- Поиск и фильтры
- Эндпоинты API (список источников, добавление, некорректный источник, список публикаций, пометить прочитанным, статистика)

Сетевые вызовы эмулируются с помощью локальных фикстур; реальные RSS-сайты не требуются.

## Конфигурация

Приложение работает без дополнительной настройки. База данных SQLite хранится в `data/rss_reader.db` и создаётся автоматически при первом запуске.

Файл `.env` и переменные окружения для локальной разработки не требуются.

## Ограничения

- Нет автоматического фонового планировщика; источники обновляются только по запросу пользователя через интерфейс.
- SQLite — файловая база данных, подходящая для локального однопользовательского использования, но не для параллельной многопользовательской эксплуатации.
- Полнотекстовый поиск использует SQLite `LIKE` (FTS5 не применяется).
- Фронтенд представляет собой одну HTML-страницу, обслуживаемую FastAPI; отдельного конвейера сборки фронтенда нет.
